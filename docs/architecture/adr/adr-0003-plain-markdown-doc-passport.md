# ADR-0003: Паспорт документації як набір Markdown-файлів у `docs/`, контроль — `doc_audit.py`

- **Статус:** Superseded by [[adr-0004-documentation-as-code-mkdocs|ADR-0004]] (2026-11-20)
- **Дата рішення:** 2026-11-14 (ЛР№10, коміт `2a29ff6` «docs(architecture): deliver design and infrastructure passport»)
- **Дата запису:** 2026-11-20 (рішення існувало неявно в ЛР№10; оформлено при міграції в кущ ADR)
- **Автор / власник:** Danylo Yakymiv
- **Пов'язані документи:** [[sdd]], [[isd]], [[documentation-regime]]

## Контекст

Аудит ЛР№10 показав, що знання про систему розкидані по README, коментарях конфігурацій і звітах. Потрібно було
швидко створити паспорт (SDD, ISD, ADR, регламент) і автоматично ловити його відставання від коду.

## Розглянуті альтернативи

| # | Варіант | Плюси | Мінуси |
|---|---|---|---|
| A | **Markdown у `docs/` + `scripts/doc_audit.py` у CI** (обрано) | нуль нових інструментів, рендер на GitHub | немає навігації, пошуку і публічного сайту; биті якорі й сторінки «поза навігацією» не ловляться |
| B | Wiki GitHub | редагування в браузері | окремий репозиторій, немає рев'ю через PR |
| C | Confluence / Notion | зручний редактор | «мертвий» формат поза Git, без версіонування разом з кодом |

## Рішення

Документи — Markdown у `docs/`; `doc_audit.py --strict` (CI-job `docs-currency`) перевіряє вік, дрейф коду,
відносні посилання і наявність усіх маршрутів API в SDD.

## Наслідки

- ✅ Паспорт з'явився за один день і живе поруч із кодом.
- ⚠️ Немає статичного сайту, навігації та пошуку; формати API дублюються в SDD (ризик розсинхронізації).
- ⚠️ Посилання на якорі, сторінки поза навігацією і зламана розмітка не перевіряються.

Ці обмеження стали контекстом [[adr-0004-documentation-as-code-mkdocs|ADR-0004]].
