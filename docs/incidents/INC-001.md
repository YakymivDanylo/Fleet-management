# INC-001 · Збій Redis зупинив запис телеметрії в PostgreSQL (legacy `telemetry-worker`)

Контрольована симуляція ЛР№12 у середовищі **sandbox** (`docker compose -p fleet_sandbox`), 10 авто публікують
показник кожні 2 с (`telemetry-simulator`). Єдиний годинник — **UTC**. Сирі дані: проба `scripts/incident_probe.py`
кожні ~15 с (`docs/lab12/evidence/incident_probe_fail.log`) і журнал дій (`docs/lab12/evidence/incident_actions.log`).

## Зведення

| Поле | Значення |
|---|---|
| Компонент | [[telemetry-worker]] (legacy) |
| Тригер збою | зовнішня залежність worker'а **Redis** недоступна (`docker compose stop redis`) |
| Початок збою | 12:11:18 |
| Виявлення | 12:12:09 — **вручну** (алерта на інжест телеметрії не існувало): `GET /vehicles/1/state` → `degraded=true`, показник старіє, черга росте. MTTD = 51 с (лише тому, що людина дивилась на пробу) |
| Серйозність | **SEV-2** — деградація ключової функції (свіжість стану парку), API доступний, даних не втрачено |
| Тимчасовий обхід | 12:13:17 — відновлення Redis (усунення тригера; дефект worker'а лишився) |
| Стабілізація | 12:13:28 — backlog 0, свіжість 1 с, `degraded=false` |
| Тривалість впливу | 2 хв 10 с (12:11:18 → 12:13:28); MTTR від виявлення — 1 хв 19 с |

## Оцінка впливу

| Що | Значення |
|---|---|
| Запити до API | 0 помилок 5xx — API відповідав 200 з fallback; **SLI-1 не зачеплено** |
| Користувачі | усі, хто дивився стан/мапу парку: 10 авто (100 % парку sandbox) показували застиглі координати й пальне до 104 с |
| Телеметрія | ≈ 600 показників (10 авто × 0,5/с × 119 с) затримано, **0 втрачено**: після відновлення `telemetry_readings` +620 рядків з 12:11:19 (ідемпотентний INSERT) |
| SLI-3 telemetry freshness | порушено 2 хвилинні вікна (12:12 і 12:13) з `lag > 60 с` → витрачено 2 з 432 хв місячного бюджету SLO (**0,46 %**) |
| SLA (`docs/slo.yaml`, SLI-3 ≥ 98 %, 864 хв/міс) | цей інцидент SLA **не порушив** (2 хв ≪ 864 хв) — лише тому, що збій прибрали за 2 хв. Без алерта той самий збій уночі тривав би до ранку: 8 год = 480 хв > бюджету SLO 432 хв (**SLO порушено**) і 56 % дозволеного SLA |

## Перевірка «очікуваної» поведінки

ADR-0001 обіцяє: «втрата Redis не втрачає даних», Redis — лише похідний кеш. Фактично інжест у джерело істини
зупинився, бо worker вважав некритичну залежність критичною. Регресійний тест, що фіксує дефект, додано в
`tests/integration/test_telemetry_worker.py::test_cache_outage_does_not_block_ingestion` — на коді станом на інцидент
**падає** (`('nack', True), ('nack', True)` замість `ack, ack`).

Аналіз причин (blameless post-mortem, RCA) і план CAPA — у роботі.
